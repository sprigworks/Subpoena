# jobrunner: adopting Subpoena from another module

A toy CI job runner in its own Go module (`example.com/jobrunner`) that adopts
Subpoena the way another service would, using only Subpoena's public packages
and commands. It exists to keep that path working: CI runs it (the `adopter`
job), so a change to Subpoena that breaks an outside adopter fails here first.

The rule: a job from an untrusted source that asks for secrets is rejected and
never runs. `Admit` is the enforcement point; the witness (`ProcWitness`)
proves no process ran; cross-examination proves the tests notice when the
rejection is removed.

## What an adopter needs

| Piece | Here | From Subpoena |
| --- | --- | --- |
| Registry | `registry/` (own names, `tier` annotations) | format and conventions |
| Generated names | `generated/go/semconv` (`make generate`, Weaver) | `weaver-templates/`, copied |
| Invariants | `invariants/` (embed package + `*.traceql`) | `go generate` runs `subpoena-invgen` |
| Tests | `runner_test.go` | `pkg/harness`, `pkg/witness` |
| Lint, cross-examination | `make lint`, `make cross` | `subpoena-lint`, `subpoena-cross` as Go tools |

The commands are pinned as Go tools (Go 1.25+), so their version is the
`github.com/sprigworks/subpoena` version in `go.mod`:

```
go get -tool github.com/sprigworks/subpoena/cmd/subpoena-lint
go get -tool github.com/sprigworks/subpoena/cmd/subpoena-cross
go get -tool github.com/sprigworks/subpoena/cmd/subpoena-invgen
```

`go.mod` replaces Subpoena with `../..` because this module lives inside the
Subpoena repository; a real adopter requires a released version instead.

## What building it found (fixed in Subpoena)

- Invariant names were generated by an `internal` package another module
  cannot run; now `cmd/subpoena-invgen`.
- Cross-examination copied the module to a temporary directory, where a relative
  `replace` (developing against a local checkout) pointed at nothing.
- A mutant whose removed statement was the only use of an import did not
  compile, so it proved nothing; subpoena-cross now drops the unused import.

`generated/go/semconv/semconv.go` was first written by hand to match the
template, on a machine without Weaver; the `adopter` CI job regenerates it with
Weaver and fails on any difference.
